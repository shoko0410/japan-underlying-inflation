# 일본 기조적 물가

일본은행 조사통계국이 매달 내는 **기조적 인플레 지표**(절사평균·가중중앙값·최빈값)와
**상승·하락 품목 비율**을 2001년부터 보여주는 정적 사이트입니다.

**한국어·일본어** 두 언어를 지원합니다. 우측 상단 버튼으로 전환하거나 `?lang=ja` / `?lang=ko`
로 직접 링크할 수 있고, 선택은 브라우저에 기억됩니다.

## 실행

```bash
npm run fetch    # 일본은행 파일을 받아 data/jpn.json + public/data.js 생성
npm start        # http://localhost:5173
```

데이터를 한 번 받아두면 `public/index.html`을 브라우저로 직접 열어도 동작합니다
(데이터를 `.json`이 아니라 `data.js`로 굽는 이유가 이것입니다 — `file://`에서는 fetch가 막힙니다).

**의존성이 없습니다.** `npm install` 을 돌릴 필요가 없고 `node_modules` 도 생기지 않습니다.
xlsx 리더까지 `node:zlib` 만으로 직접 구현했습니다.

## API 키

| 키 | 필수 | 발급처 | 용도 |
|---|---|---|---|
| `ESTAT_APP_ID` | **아니오** | [e-stat.go.jp/api](https://www.e-stat.go.jp/api/) | 총무성 공식 総合·コア·コアコア CPI |

**핵심 계열은 키 없이 동작합니다.** 일본은행 파일은 인증이 필요 없습니다. e-Stat 키는 비교용
공식 CPI 세 줄(総合·コア·コアコア)을 얹을 때만 쓰이고, 없으면 그 세 줄만 빠진 채로 빌드됩니다.

`--strict` 는 키가 **설정돼 있는데 값이 안 올 때만** 실패합니다. 키를 아예 안 넣은 건 의도된
선택이지 회귀가 아니기 때문입니다.

## 데이터 출처

주력 계열은 전부 일본은행 조사통계국의 파일 하나에서 나옵니다 —
[기조적인 인플레율을 파악하기 위한 지표](https://www.boj.or.jp/research/research_data/cpi/index.htm)
(`cpirev.xlsx`, 약 79KB). **공식 CPI 발표 2영업일 뒤 오후 2시(JST)** 에 갱신됩니다.

| 계열 | 일본은행 표기 | 설명 |
|---|---|---|
| 절사평균 | 刈込平均値 | 가격 변화 순으로 줄 세워 양끝을 잘라낸 가중평균 |
| 가중중앙값 | 加重中央値 | 지출 비중 기준 한가운데 품목의 변화율 |
| 최빈값 | 最頻値 | 가장 많은 품목이 몰려 있는 변화율 |
| 코어 | 除く生鮮食品 | **생선식품만** 제외 — 에너지는 포함 |
| 코어코어 | 除く生鮮食品・エネルギー | 생선식품·에너지 제외 |
| 식료품·에너지 제외 | 除く食料・エネルギー | 미국식 Core에 해당 |
| 상승/하락 품목 비율 | 上昇/下落品目比率 | 전년 대비 오른·내린 품목의 비중 |

비교용 공식 CPI 3종(総合·コア·コアコア)은 e-Stat의 2025년 기준 표(`0004052037`, `tab=3` 전년동월비)
에서 받습니다. 이 표는 **1971년까지 연결된 값**을 담고 있어 일본은행 파일과 달리 기준 연결이
필요 없습니다.

공식치와 일본은행 추계치를 나란히 놓으면 특수요인의 크기가 그대로 보입니다 — 2026년 7월 기준
공식 코어 **1.8%** vs 일본은행 **2.3%**, 즉 에너지 부담 경감책이 공식 수치를 0.5%p가량 누르고
있습니다.

경기후퇴 구간은 내각부 경기기준일자(景気基準日付)이며, 수가 적고 확정이 수년씩 늦어
`scripts/fetch-data.mjs` 에 표로 박아뒀습니다.

### 미국판과 다른 점

같은 구조의 [미국판](https://github.com/shoko0410/us-underlying-inflation)에서 제일 손이 많이
갔던 부분이 **여기선 통째로 불필요합니다.** 댈러스 연준은 품목별 가격 변화 분포를 최근 13개월치만
공개해서 BEA 원자료로 1977년까지 직접 복원해야 했는데, **일본은행은 분포에서 읽는 지표를 직접,
2001년까지 공표**합니다. 그래서 이 저장소에는 복원 스크립트도 검증 사다리도 없습니다.

### 특수요인 제거

일본은행 계열은 전부 **"특수요인"을 제거한 조사통계국 추계치**입니다 — 소비세율 변경, 교육
무상화(2026년 4월 급식 무상화 포함), 2021년 휴대폰 요금 인하, 여행 지원 사업, 전기·가스·휘발유
부담 경감책. 정책이 만든 일회성 단차를 걷어내야 시계열이 비교 가능해지기 때문인데, 그만큼
**뉴스에 나오는 총무성 공식 숫자와는 어긋납니다.**

### 기준연도

일본 CPI는 5년마다 기준연도를 개정하고, 파일은 기준별로 열을 나눠 싣습니다. 각 기준이 자기 5년
구간을 **겹침 없이** 덮고 있어 월마다 값이 있는 열을 그대로 이어붙였습니다. 전년비 "비율"이라
지수처럼 연결·재기준화할 필요가 없습니다.

```
2000년 기준  2001-01 ~ 2005-12      2015년 기준  2016-01 ~ 2020-12
2005년 기준  2006-01 ~ 2010-12      2020년 기준  2021-01 ~ 2025-12
2010년 기준  2011-01 ~ 2015-12      2025년 기준  2026-01 ~
```

파서는 행·열 번호를 고정하지 않고 내용으로 찾습니다. 헤더에는 엑셀 **후리가나**가 붙어 있고
(`刈込平均値（前年比、％）カコヘイキンチ`), 시트 오른쪽에는 같은 이름을 쓰는 **분기 블록**이
따로 있어서, 둘 다 걸러내지 않으면 조용히 틀린 값이 나옵니다.

## 자동 갱신

`.github/workflows/update.yml` 이 **매일 06:40 UTC**(일본시간 15:40)에 실행됩니다. 일본은행이
오후 2시에 올리므로 그 뒤입니다.

발표일에만 맞추지 않고 매일 도는 이유는, CPI 발표일이 매달 바뀌고 수정이 비정기적으로 나오며
5년마다 기준연도가 개정되기 때문입니다. 대신 **값이 실제로 바뀌었을 때만 커밋**합니다 —
`generatedAt` 은 데이터가 변했을 때만 갱신되므로, 변화가 없는 날은 출력이 바이트 단위로 동일해
아무 기록도 남지 않습니다.

### 저장소 준비

```bash
gh secret set ESTAT_APP_ID --body '<발급받은 appId>'   # 선택
```

Settings → Pages → Source 를 **GitHub Actions** 로 설정하면 됩니다.

> GitHub은 저장소가 60일간 활동이 없으면 예약 워크플로우를 자동으로 비활성화합니다.
> CPI가 매달 나오니 보통은 커밋이 계속 생겨 문제없습니다.

## 구조

```
scripts/fetch-data.mjs   일본은행(+ 선택적 e-Stat) → data/jpn.json, public/data.js
scripts/serve.mjs        정적 서버
lib/boj.mjs              cpirev.xlsx 파싱 · 기준연도 연결 · 후리가나/분기 블록 처리
lib/xlsx.mjs             무의존성 xlsx 리더 (node:zlib 만 사용)
public/                  index.html · app.js · styles.css · i18n.js · data.js
```

화면에 나오는 모든 문자열은 `public/i18n.js` 한 파일에 있습니다. `app.js` 에는 어느 언어의
문자열도 하드코딩되어 있지 않고, `index.html` 은 `data-i18n` / `data-aria` 키로 표시된 자리에
한국어를 인라인으로 담고 있습니다 — 자바스크립트가 없어도 한국어로는 읽힙니다.

차트 색상은 dataviz 팔레트의 카테고리 슬롯을 고정 순서로 씁니다. 계열을 꺼도 남은 선의 색이
바뀌지 않습니다.
